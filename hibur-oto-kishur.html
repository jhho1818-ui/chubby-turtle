עדכון אוטומטי לאותו קישור

הגדרה חד-פעמית · אחר כך כל עדכון הוא לחיצה כפולה אחת

⚠️ למה זה עדיף על גרירת ZIP.
גרירה ל-Netlify Drop יוצרת בכל פעם אתר חדש עם כתובת חדשה. אחרי שלושה עדכונים יש שלוש כתובות, אף אחד לא יודע איזו נכונה, ומי שכבר התקין את האפליקציה בטלפון נשאר תקוע על הישנה.

⚠️ החיבור ל-GitHub פותר בדיוק את זה: הכתובת לעולם לא משתנה. אתה דוחף, Netlify בונה לבד, וכל מי שהתקין מקבל את העדכון בפתיחה הבאה — בלי להתקין מחדש ובלי לדעת שקרה משהו.

1 מתקינים Git

פעם אחת בלבד, מ-git-scm.com. הכול ברירת מחדל, Next עד הסוף.

2 יוצרים מאגר ריק ב-GitHub

  1. נכנסים ל-github.com ➜ New repository
  2. שם: למשל chubby-turtle
  3. חשוב: לא לסמן שום תיבה (בלי README, בלי .gitignore, בלי רישיון) — אחרת הדחיפה הראשונה תיתקל בהתנגשות
  4. Private אם אתה רוצה שהקוד לא יהיה גלוי. האתר עצמו יישאר ציבורי בכל מקרה.
  5. מעתיקים את הכתובת שמופיעה, בצורה https://github.com/…/chubby-turtle.git

3 מחברים את התיקייה

לוחצים ימני על התיקייה של צאבי ➜ Open in Terminal (או Git Bash), ומדביקים:

git init
git add .
git commit -m "Chubby first commit"
git branch -M main
git remote add origin https://github.com/YOUR-NAME/chubby-turtle.git
git push -u origin main

בפעם הראשונה ייפתח חלון התחברות ל-GitHub. זה קורה פעם אחת.

⚠️ והנה הרווח השני, שהוא אולי החשוב יותר: מרגע זה יש לכל שינוי בקוד חותמת זמן שנרשמה מחוץ למחשב שלך, על שרת של GitHub. זו הראיה החזקה ביותר לבעלות — חזקה בהרבה מכל סימון בתוך הקוד, כי תאריך שנכתב במחשב שלך אפשר לטעון שהוא שונה, ותאריך אצל צד שלישי — לא.

4 מחברים את Netlify למאגר

  1. בעמוד האתר ב-Netlify ➜ Project configuration
  2. ➜ Build & deploy ➜ Link repository
  3. בוחרים GitHub, מאשרים גישה, ובוחרים את המאגר
  4. ההגדרות כבר כתובות בקובץ netlify.toml שבתיקייה, ולכן לא צריך למלא כלום. אם בכל זאת נשאלים:
    Build command: node tools/build-dist.js
    Publish directory: dist

5 מכאן והלאה

לחיצה כפולה על publish.bat.

הסקריפט מעלה את מספר גרסת המטמון, כותב מחדש את קובץ הבעלות OWNERSHIP.json עם תקציר SHA-256 לכל קובץ, דוחף ל-GitHub, ו-Netlify בונה ומפרסם לאותה כתובת תוך כדקה.

⚠️ שלב אחד שקל לשכוח, ובלעדיו שום עדכון לא מגיע לאיש.
ה-Service Worker מגיש למשתמש את מה ששמור אצלו במטמון, ומחליף אותו רק כששם המטמון משתנה. אפשר להעלות גרסה חדשה מושלמת, לראות אותה עובדת אצלך (כי אצלך אין מטמון ישן) ולחשוב שהכול תקין — בזמן שכל מי שהתקין ממשיך לראות את הישנה לנצח.

בדיוק בגלל זה publish.bat מעלה את המספר אוטומטית לפני כל דחיפה. אם אתה דוחף ידנית עם git push, הרץ קודם: node tools/cache-version.js --fix
